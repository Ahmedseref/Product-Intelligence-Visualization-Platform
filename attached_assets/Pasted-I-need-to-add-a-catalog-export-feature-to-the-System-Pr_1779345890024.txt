## Word document structure

Build the .docx file in a new server endpoint or as a client-side generation function. Given the complexity, generate it server-side.

### New endpoint: POST /api/systems/export-catalog

Request body:
{
  systemIds: string[],          // which systems to include
  options: {
    includeCover: boolean,
    includeCrossSection: boolean,
    includeParameters: boolean,
    includeProducts: boolean,
    includeAlternatives: boolean,
    includeRecommendations: boolean,
    hideStockCodes: boolean,
    hideSuppliers: boolean,
    hideStatus: boolean,
    format: 'docx' | 'pdf'
  }
}

Response: the generated .docx file as a binary stream with Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document and Content-Disposition: attachment; filename="systems-catalog-[date].docx"

### Server logic

Fetch all needed data for requested systemIds:
- System records (name, type, substrate, humidity, duty, finish, description, preview_note, status)
- Layers for each system (ordered by position)
- Default product per layer (the product with is_default = true, or first product)
- Alternative products per layer (all non-default products)
- Qualification tags per product (substrate_types, humidity_tolerance, duty_rating, finish_type)

Build the docx document using the docx library:

```javascript
import { Document, Packer, Paragraph, Table, TableRow, TableCell, TextRun, ImageRun, HeadingLevel, BorderStyle, WidthType, AlignmentType, ShadingType } from 'docx';
```

### Document sections

#### Section 1 — Cover page (if includeCover)

A cover page with:
- Company name (fetch from proforma_settings or a settings table — if not available, use "Flooring & Waterproofing Systems")
- Title: "Technical Systems Catalog"
- Export date
- Summary stats: X systems, Y active, Z draft
- System type breakdown: Epoxy · PU · Polyurea · Acrylic counts
- Table of contents: system name → page number (Word auto-updates TOC on open)
- Page break after

Use docx HeadingLevel.HEADING_1 for the title, normal paragraphs for metadata. The cover page background should use a shading on a full-width paragraph to create a colored header band — use the docx shading feature with a blue/teal fill.

#### Section 2 — One page per system

For each system, one Word section (adds page break between systems):

**System header block:**
- System name: Heading 2 style, bold, 16pt
- Type badge + status badge: inline text runs with colored background shading
- Description paragraph: normal text, italic, 11pt

**Two-column layout using a borderless table (2 cells):**

Left cell (~40% width):
- Sub-heading "Build-up cross-section"
- The cross-section diagram rendered as a PNG image embedded in the document
  - Generate the SVG cross-section server-side as a string
  - Convert SVG to PNG using the `sharp` library (already check if installed — if not, use a simple SVG-to-PNG approach or embed the SVG as-is via base64 in an ImageRun)
  - If sharp is not available, skip the image and use a text-based cross-section table instead (see fallback below)
- Sub-heading "System parameters"
- A 2-column table (parameter name | value) with light gray header row, no outside border, thin inside borders

Right cell (~60% width):
- Sub-heading "Layer products"
- For each layer (ordered primer → base coat → topcoat):
  - A colored table row for the layer header (background color matching layer position: primer=amber #FAEEDA, base_coat=blue #E6F1FB, topcoat=green #EAF3DE)
  - Layer name + position badge in the header row

  - Qualification tags as comma-separated text: "Substrate: Concrete, Steel | Humidity: Dry | Duty: Heavy"

- Recommendation box (if includeRecommendations and preview_note exists): a table cell with green background shading (#EAF3DE) containing the recommendation text

**Page break** after each system

#### Cross-section fallback (if image generation not available)

Use a docx table instead of an image:
- Each layer is a table row with a left border colored by layer type (use left border color in docx)
- Layer number | Layer name | Position badge
- Bottom row: dashed border, "Structural substrate: [value]"
- This is simpler but still professional

## Client-side: triggering and downloading

In the System Preview tab component:

When "Generate catalog" is clicked:
1. Show a loading state: "Generating catalog... this may take a few seconds"
2. POST to /api/systems/export-catalog with the selected options and system IDs
3. Receive the binary response
4. Trigger browser download: create a Blob from the response, create an object URL, click a hidden anchor element
5. Show success toast: "Catalog exported — [X] systems, [date].docx"

```javascript
const response = await fetch('/api/systems/export-catalog', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ systemIds, options })
});
const blob = await response.blob();
const url = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = `systems-catalog-${new Date().toISOString().split('T')[0]}.docx`;
a.click();
URL.revokeObjectURL(url);
```

## Rules
- Install docx via npm install docx — check package.json first to avoid duplicate
- Check if sharp is already installed — use it for SVG→PNG if available, fall back to text table if not
- Never use html2canvas for the Word export — it produces non-editable images
- The hideStockCodes, hideSuppliers, hideStatus options must be applied at the data level before building the document — not by styling text as white
- Systems with no products assigned should still export with empty layer cards and a note "No products assigned"
- Systems with no parameters set show "Not configured" in the parameters table
- The TOC on the cover page uses Word's built-in TOC field (docx library supports this via TableOfContents) — it updates when the user opens the file and clicks "Update field"
- The endpoint must stream the file, not load it all in memory — use Packer.toBuffer() then res.send(buffer)
- After implementation test: export 2 active systems as Word, open in Word/LibreOffice, verify: (1) each system on its own page, (2) layer cards have colored backgrounds, (3) parameters table is readable, (4) stock codes hidden when option is checked, (5) file is editable (not an image)
