## Feature 2 — Formula engine

### Formula syntax
Formulas are strings containing:
- {qty} — row quantity
- {unit_price} — row unit price
- {total} — row subtotal (qty × unit_price, or the custom total formula result)
- {col:ColumnName} — value of any other column by its label name
- Standard math operators: + - * / ( )
- Numeric literals

Examples:
- {qty} * {col:Net Weight} — total net weight for that row
- {qty} * {unit_price} * (1 - {col:Discount%} / 100) — unit price with row-level discount
- {col:Gross Weight} * 2.5 — freight cost at 2.5 per kg
- {qty} * {col:Net Weight} * 1.15 — net weight with 15% buffer

### Formula evaluation function
Create a pure utility function evaluateFormula(formula: string, row: InvoiceRow, columns: Column[]): number

The function:
1. Takes the formula string
2. Replaces {qty} with row.qty
3. Replaces {unit_price} with row.unit_price
4. Replaces {total} with computeRowTotal(row, columns) — see below
5. For each {col:Name} token, finds the column with that label and substitutes row.custom_values[col.id] — if the referenced column is itself a formula column, recursively evaluates it (max depth 3 to prevent infinite loops)
6. Evaluates the resulting numeric expression safely using Function constructor wrapped in try/catch — returns 0 on error

### Row total formula
Add a "Total column formula" control in the Columns panel (below the column list):
- Select: "Default (qty × unit price)" / "Custom formula"
- When Custom: a formula input appears
- This formula overrides how the Total column is computed for every row
- Stored as total_formula in the column_config JSONB field on the proforma

computeRowTotal(row, columns, totalFormula): number:
- If totalFormula is null or 'default': return row.qty * row.unit_price
- If custom formula: return evaluateFormula(totalFormula, row, columns)
- The subtotal (sum of all rows) and all financial calculation steps use computeRowTotal per row

### Formula column rendering
In the table:
- Formula columns show a small ƒ badge in the column header
- Cell values are read-only, computed from evaluateFormula on every render
- If formula evaluation fails (syntax error, missing column), show "—" in the cell with a warning tooltip: "Formula error — check column references"
- Values are formatted with 2 decimal places

In the preview (right panel):
- Formula column values show as plain numbers with 2 decimal places
- No ƒ badge in the printed preview

### Row-level discount / markup column (example preset)
Add a preset button "Add discount column" that adds a pre-configured setup:
- A number column named "Discount %" with unit "%"  
- Overrides the total formula to: {qty} * {unit_price} * (1 - {col:Discount%} / 100)
This gives the user a one-click Excel-like per-row discount without manual formula writing.

## Integration with financial calculations
The existing financial calculation steps (VAT, freight, etc.) run on the invoice subtotal. The subtotal must always use computeRowTotal — so if a custom total formula is set, the subtotal correctly reflects it. This means:

computeFinancials(rows, columns, totalFormula, calcSteps, currency):
1. subtotal = rows.reduce((sum, row) => sum + computeRowTotal(row, columns, totalFormula), 0)
2. Run calc steps in order against running total
3. Return { subtotal, steps, finalTotal }

No changes needed to the calc steps UI — just ensure the subtotal input to it uses computeRowTotal.
