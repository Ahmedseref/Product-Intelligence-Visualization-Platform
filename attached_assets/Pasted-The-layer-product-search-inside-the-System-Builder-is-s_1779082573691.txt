## The 5 problems to fix

### Problem 1 — System type is not filtering layer products

When a system has a material type (Epoxy, PU, Polyurea, Acrylic), the product search inside each layer must exclude products from incompatible system type families.

The system type is already stored on the system record. The product's system type family can be determined from two sources (use both):
- product_qualification_tags.compatible_system_types (if set)
- The product's taxonomy node path — if a product is in "Polyurea Waterproofing" branch, it belongs to the Polyurea family. If it's in "Epoxy Waterproofing & Coatings" or "Epoxy Paints", it belongs to the Epoxy family. Use the existing taxonomy path logic already in the codebase.

Hard exclude rule: if the system type is Epoxy, do NOT show products that are exclusively Polyurea, Acrylic, or PU (i.e. products that have compatible_system_types set and it does not include Epoxy, AND the taxonomy path does not include any Epoxy branch). Products with no qualification tags at all should NOT be hard-excluded by system type — they fall through to the scoring tier.

Taxonomy system type mapping (use these branch codes and names):
- Epoxy: node codes containing EPC, EP, EPP, IF (Industrial Flooring Epoxy), EPC branches
- PU / Polyurethane: node codes PUP, PP, PW&B, PF
- Polyurea: node code PW (Polyurea Waterproofing)
- Acrylic: node codes AWM, AS, FP&SC (when acrylic-based)
- Bitumen/Cement: BBW, CBW, PB — these are standalone and should be excluded from all system types unless the system is Generic/Other

### Problem 2 — Substrate filter must use ANY overlap logic, not exact match

Currently the layer substrate filter requires the product's substrate to exactly match the system substrate. This is wrong.

Fix: if the system has substrate = ["Concrete", "Screed"], a product with substrate_types = ["Concrete", "Steel"] MUST match because Concrete is in both lists.

The matching rule: a product passes the substrate filter if its substrate_types array shares at least one value with the system's substrate array. If substrate_types is null or empty (product has no tags), do not exclude it — it falls through to the scoring tier.

The substrate field on the system is currently a single varchar. Check whether system_substrate stores a single value or an array. If it is a single varchar:
- Extend the system_substrate field to support comma-separated values OR change it to a JSONB array column
- If changing to JSONB, run npm run db:push and update all existing rows to wrap single values in an array: UPDATE systems SET system_substrate = jsonb_build_array(system_substrate) WHERE system_substrate IS NOT NULL AND jsonb_typeof(system_substrate::jsonb) = 'string'
- Update the system parameter header UI to allow multi-select for substrate (use checkboxes or a multi-select component matching the existing style) — this replaces the current single dropdown

### Problem 3 — Layer position filter must be strict, not loose

When the user is adding a product to a layer that has layer_position = 'base_coat', the product search must prioritize products tagged as base_coat and hard-exclude products tagged as 'primer'.

Strict layer position rules:
- Primer layer slot → hard-exclude products with layer_position = 'topcoat' or 'standalone'. Show base_coat products only if no primer products exist.
- Base coat layer slot → hard-exclude products with layer_position = 'primer'. Do not show primers in a base coat slot ever.
- Topcoat layer slot → hard-exclude products with layer_position = 'primer' and layer_position = 'base_coat'.
- Standalone layer slot → show all, no position exclusions.
- Products with layer_position = null → never hard-exclude, but score lower.

The layer's position type is already stored on the layer record (check the schema for the field name — it may be layer_position or layer_type). Use it.

### Problem 4 — Score and sort products by match quality

After applying hard exclusions (problems 1, 2, 3), score every remaining product and sort by score descending. This replaces any existing sort order.

Scoring function (compute server-side, return score with each product):

```javascript
function scoreProduct(product, qualTags, layer, system) {
  let score = 0;

  // Layer position match
  if (qualTags?.layer_position === layer.layer_position) score += 4;
  else if (qualTags?.layer_position === null) score += 0;

  // System type match
  if (qualTags?.compatible_system_types?.includes(system.system_type)) score += 3;

  // Substrate overlap (count overlapping substrates)
  const sysSubstrates = Array.isArray(system.system_substrate) 
    ? system.system_substrate 
    : [system.system_substrate].filter(Boolean);
  const prodSubstrates = qualTags?.substrate_types || [];
  const overlap = prodSubstrates.filter(s => sysSubstrates.includes(s)).length;
  score += overlap * 2;

  // Humidity match
  if (qualTags?.humidity_tolerance === system.system_humidity) score += 2;

  // System ready boost
  if (qualTags?.is_system_ready === true) score += 3;

  // Qualification confidence boost
  if (qualTags?.confidence_overall === 'HIGH') score += 1;

  // Duty match
  if (qualTags?.duty_rating === system.system_duty) score += 1;

  return score;
}
```

Return the score with each product in the API response. Do not display the raw score number in the UI — instead display a match quality label:
- score >= 10: "Best match" — show a small green dot
- score >= 6: "Good match" — show a small blue dot  
- score >= 3: "Partial match" — show a small amber dot
- score < 3 AND is_system_ready = true: "Qualified" — show a small gray dot
- score < 3 AND is_system_ready = false: no dot, product shown in muted style

The dot and label appear at the far right of each product row in the layer product search results, before the + button. Keep the existing row layout — just add this small indicator.

### Problem 5 — Unqualified products appear mixed with qualified ones

Currently unqualified products (is_system_ready = false or no qualification tags) appear in the same list as fully qualified products with no visual distinction.

Fix the ordering: always show qualified products first (is_system_ready = true), then unqualified products below a visible divider line labeled "Unqualified products — not yet tagged". The "Show all" button should already handle revealing/hiding unqualified products — if it does, keep that behavior and just add the divider. If it doesn't, add a toggle at the bottom of the qualified list: "Show X unqualified products ↓".
