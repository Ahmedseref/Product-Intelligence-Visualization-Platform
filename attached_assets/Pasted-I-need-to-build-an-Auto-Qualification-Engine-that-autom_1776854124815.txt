I need to build an Auto-Qualification Engine that automatically assigns Substrate, Humidity, Duty, and Finish tags to products using keyword inference from product name, description, and taxonomy path. This replaces the need for manual entry in most cases. The engine runs on demand (bulk) and automatically when a new product is saved.

## Context
This app uses React/TypeScript, Tailwind CSS, Express.js, Drizzle ORM, PostgreSQL. The Product Qualification tab already exists inside System Builder. The qualification_tags and qualification_vocabularies tables already exist with these fields:
- product_qualification_tags: product_id, substrate_types (jsonb array), humidity_tolerance, duty_rating, finish_type, is_system_ready, qualified_at
- qualification_vocabularies: vocab_type, value, label

Before writing any code, read the full existing Product Qualification tab component, server/routes.ts, and shared/schema.ts.

## Part 1 — Inference engine (server-side utility)

Create a new file: server/qualificationEngine.ts

This file exports a single function:
inferQualificationTags(product: { name: string, description: string, nodeId: string }, taxonomyPath: string[])

It returns:
{
  substrate_types: string[],
  humidity_tolerance: string,
  duty_rating: string,
  finish_type: string,
  confidence: {
    substrate: 'high' | 'medium' | 'low' | 'none',
    humidity: 'high' | 'medium' | 'low' | 'none',
    duty: 'high' | 'medium' | 'low' | 'none',
    finish: 'high' | 'medium' | 'low' | 'none',
    overall: 'high' | 'medium' | 'low' | 'none'
  },
  sources: {
    substrate: string,  // e.g. "taxonomy:PW" or "name:steel" or "description:cementitious"
    humidity: string,
    duty: string,
    finish: string
  }
}

The function uses ONLY string matching — no external AI API calls. All inference is deterministic keyword + taxonomy rules.

- 'none': nothing resolved at all

## Part 2 — Bulk inference API endpoint

Add to server/routes.ts (do not modify existing routes):

POST /api/qualification-tags/auto-infer
Body: { productIds: string[] } — if empty array, run on ALL products

For each product:
1. Fetch product name, description, node_id from products table
2. Fetch taxonomy path (walk tree_nodes from that node_id up to root, collect names and codes)
3. Run inferQualificationTags()
4. Return results — do NOT auto-save. Return suggestions only.

Response shape:
{
  results: Array<{
    product_id: string,
    product_name: string,
    taxonomy_path: string,
    suggested: { substrate_types, humidity_tolerance, duty_rating, finish_type },
    confidence: { substrate, humidity, duty, finish, overall },
    sources: { substrate, humidity, duty, finish },
    already_qualified: boolean  // true if product_qualification_tags record exists with is_system_ready=true
  }>
}

POST /api/qualification-tags/auto-save-batch
Body: { tags: Array<{ product_id, substrate_types, humidity_tolerance, duty_rating, finish_type, is_system_ready }> }
Saves all provided records using upsert. Returns count of saved records.

Also add a trigger on the existing POST /api/products endpoint:
After a new product is successfully saved, call inferQualificationTags() for that product and store the result in a new table column or return it in the product creation response so the frontend can prompt the user. Do not auto-save the tags — just return the suggestions in the POST /api/products response under a key called "qualification_suggestions".
